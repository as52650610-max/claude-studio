# 05 歌詞對齊與字幕

歌詞 MV 最容易被看出破綻的地方就是歌詞：錯一個字、早亮半秒、被畫面蓋住、還沒讀完就消失。這一章講怎麼把歌詞的時間做準、怎麼排、怎麼檢查。

## 文本：官方歌詞優先

- **一定要用官方歌詞文本**（歌手官網、唱片內頁、官方 MV 字幕）。語音辨識出來的文字只能拿來對時間，不能當成最終歌詞（haiy）。
- 繁簡要一致：用繁體中文發布就整份轉成繁體，並確認字型涵蓋所有字。
- 外語歌：原文一行、翻譯一行，翻譯字級較小、時間相同。翻譯要註明譯者。

## 歌詞的版權

在畫面上顯示歌詞是同人 MV 的常態，但**公開的程式庫不要放歌詞全文**。Nyankomintsu 的做法值得照抄：

- 版本控制裡只放 `lyrics.timing.json`：每句的時間、段落、是否為關鍵句，**沒有文字**。
- 使用者自己提供歌詞檔，`fill` 指令把文字填回時間表，填不上的句子會列出行號與時間，而不是帶著空白去渲染。
- 發布前跑檢查：版本控制的檔案裡不能出現連續 4 個字以上的歌詞片段，也不能有音檔。

本專案的對應指令：`lyrics strip`（輸出只有時間的檔案）、`lyrics fill`（填回文字）、`qa --check-lyrics`（發布前檢查）。

## 三種對齊路線

| 路線 | 適合 | 精度 | 成本 |
|---|---|---|---|
| 1. 現成 LRC | 能找到逐句或逐字時間的歌詞檔 | 逐句準、逐字看來源 | 最低 |
| 2. 手動點拍 | 任何歌、特別是自由節奏或語音辨識失敗的歌 | 你的手有多準就多準 | 一首歌約 10–20 分鐘 |
| 3. 自動對齊 | 需要逐字時間的卡拉 OK 效果 | 好的流程可到數十毫秒 | 需要安裝模型、要人工校對 |

### 路線 1：匯入 LRC

```
node tools/studio.mjs lyrics import projects/my-mv song.lrc
```

LRC 解析規則（取自 paint-mv）：

- 空白時間行代表上一句結束。
- 同一時間出現兩行（通常是翻譯）時，第二行會被丟棄並警告；需要翻譯請放在 `translation` 欄位。
- 沒有結束時間時，結束 = min(下一句開始 − 0.1 秒, 開始 + max(2 秒, 2 倍字數掃過時間))。
- 警告：重疊、短於 0.6 秒、太寬（1080p、50 px 字級時約 33 個中文字或 70 個拉丁字母）、第一句在 1 秒以內。
- 支援增強型 LRC（`<00:12.34>` 逐字時間戳）。

### 路線 2：手動點拍

用瀏覽器打開 `tools/lyric-tapper.html`（完全離線）：

1. 載入歌曲與歌詞文字（一行一句）。
2. 播放時每句開始按一下空白鍵；需要逐字時間就切換成逐字模式，每個字按一下。
3. 可以慢速播放、倒退、單句重錄。
4. 匯出 `lyrics.json` 或 LRC。

自由節奏、現場錄音、語音辨識認不出來的唱腔（假音、拖長音、和聲）用這條路最可靠。

### 路線 3：自動對齊

高收藏作品用過的流程：

| 作品 | 流程 |
|---|---|
| 《三千年夜》MV | Demucs 分離人聲 → wav2vec2 強制對齊 → 人工修正 |
| Faker 生涯 MV | Demucs → faster-whisper large-v3 分別辨識混音與人聲軌 → 逐字對齊 → 動態規劃把每個字對到偵測到的人聲起音 |
| mexicat P(doom) | 多組分軌 → 兩種 CTC 模型 → 全曲一次的受限 Viterbi 對齊 → whisper 交叉檢查 → 疑難處手動錨點（每個錨點都寫下證據）→ 起音微調 |
| 熱異常 PV | 有 UTAU／VOCALOID 樂譜時，樂譜直接給出每個音節的開始時間，比任何辨識都準 |

本專案的 `tools/py/lyrics.py` 內建不需要模型的部分（解析、填字、檢查、對齊到人聲起音），需要模型的部分（Demucs、faster-whisper）是**選用**的，裝了才啟用。

自動對齊的陷阱（paint-mv 實測）：

- **不要開語音活動偵測（VAD）**：音樂會讓它誤判成靜音而跳過歌詞。
- whisper 的病：吞掉停頓前的字、重複、長度為 0 的字、快得不合理的字（中文每字少於 0.08 秒）。
- 用提示詞餵歌詞時，whisper 可能在間奏「背誦」歌詞；長度為 0 的字超過 20% 就要警告。
- 小模型的逐句開始時間中位誤差約 0.34 秒，**有好的 LRC 就用 LRC**。

### 逐字時間

言炎的提醒：**不要把一句的時間平均分給每個字**。拖長音、轉音、和聲都會讓平均分配錯得很明顯。

- 卡拉 OK 逐字亮起需要真正的逐字時間（路線 2 的逐字模式或路線 3）。
- 只有逐句時間時，引擎會用加權估計（中文字 1、拉丁字母 0.25、空白 0.1、標點 0），並在資料裡標記為「估計」。估計值適合整句出現的設計，不適合逐字亮起。
- **用人聲分軌的起音當逐字時間**（中文多半一字一音時）：`studio analyze --stems` 會在 songmap 裡寫下人聲起音與強度。分軌上的假起音（殘響或回音的尾巴、長音裡的抖動）分析器會自己濾掉（[04](04-music-timing.md#分析流程)）；本專案的範例 [song-to-mv](../examples/song-to-mv/) 45 個字剛好量到 45 個起音。起音依序一字一個，每個字結束在下一個字開始；寫成 JSON（每句帶 `chars`）後用 `studio lyrics import` 匯入，量到的時間不會被標成「估計」。數不合（起音比字多或少）時不要硬配，那一句改用路線 2 點拍。

## 對齊後一定要做的事

```
node tools/studio.mjs lyrics check projects/my-mv
node tools/studio.mjs lyrics snap projects/my-mv
```

- `check`：閱讀時間、重疊、行寬、第一句時間、缺字（字型沒有的字）。
- `snap`：把每句開始對齊到最近的人聲起音或半拍（只在差距小於門檻時移動，並列出移動了哪些句子）。
- **人耳校對**：列出最不確定的 10 個時間點，請你聽（Nyankomintsu 的「前十名請人耳確認」）。

## 歌詞資料格式

`data/lyrics.json`：

```json
{
  "version": 1,
  "source": "官方歌詞，取自 ……",
  "lines": [
    {
      "i": 0,
      "start": 12.34,
      "end": 15.80,
      "text": "……",
      "translation": "",
      "section": "verse1",
      "keyword": false,
      "chars": [{ "c": "……", "start": 12.34, "end": 12.61, "est": false }]
    }
  ]
}
```

## 排版

### 歌詞是畫面裡的事件，不是字幕

Faker MV 的做法：每一句歌詞都有自己的「演出模板」，文字是畫面的一部分。HyperFrames 把每個片語分成三種處理：

- **略過**：填充字，不顯示。
- **軌道**：照字面顯示在固定位置（預設）。
- **嵌入**：稀少的高潮字，合成到主體後面；每拍最多一個，不連續使用。

### 中文的排版單位

取自 Hypit 的字幕技巧，對中文歌詞特別重要：

- **時間的單位是字，閱讀的單位是片語**。一個顯示單位要是有意義的片語。
- 複合詞、名字、修飾語＋受詞要放在一起；不要重複出現很小的分組，觀眾會一直重新找字。
- 中英混排時依**實際量出來的寬度**排版，不要用字數估計（一個英文品牌名可能占好幾個中文字寬）。
- 強調方式和分組無關：卡拉 OK 有「目前字」與「已唱過」兩種狀態；亮起方式有「整組一起亮」與「字內掃過」；出現方式有「全部一起」、「開唱時出現」、「打字機」。
- 文字超出畫面時，先判斷是分組的問題還是字型樣式的問題，再改。

### 字級與字型（1080p 參考值，取自 EGSECDA）

| 角色 | 字級 |
|---|---|
| 巨字（裁切出畫面，一鏡一個） | 畫面高度的 110–160% |
| 主視覺大字 | 200–300 px |
| 橫排歌詞 | 96–120 px，行距 1.35 |
| 直排歌詞 | 84–104 px，欄距 1.6 em |
| 次要文字 | 38–44 px |
| HUD 小字 | 20–24 px，不透明度 60–70% |

- 每段最多 3 種字型家族，每鏡最多 2 種字重。
- **中文不要用合成的粗體或斜體**（瀏覽器自動加粗會糊）。需要粗體就載入真正的粗體字重。
- 直排時：長音符、破折號、刪節號、波浪號、括號、引號要旋轉；頓號與句號移到右上。
- 直排適合主歌與內心獨白，橫排適合副歌，交叉排適合「キメ」（定格強調）。
- 文字安全區：畫面的 90%（標題）；重要小字避開底部中央約 80 px（平台播放器會蓋住）。

### 可讀時間

| 來源 | 規則 |
|---|---|
| lemo-opuscar | 字幕至少 1.8 秒，且至少等於唸完的時間＋0.6 秒；中文停留 ≈ 字數 ÷ 4.5 ＋ 1.5 秒；標題卡至少 4 秒 |
| brag | 從完全出現開始算，每個詞約 0.3 秒；短標籤 0.8 秒；標題至少 1.2 秒 |
| Nyankomintsu | 一般歌詞放在固定字幕帶，從這句開唱顯示到下一句開唱 |

歌詞 MV 的特例：歌詞顯示時間受演唱時間限制。原則是**唱多久就至少顯示多久**，可以提早最多 0.4 秒以暗色預告，但亮起的進度永遠不能跑在歌聲前面（mexicat）。

觀眾抱怨最多的是「字還沒讀完就翻頁了」（Vibe 知識類影片的留言）。

### 字型授權與載入

- 只用開源授權字型（SIL OFL 等），在 `CREDITS.md` 列出。常見可用的繁中字型：Noto Sans TC／Noto Serif TC、思源黑體／思源宋體、霞鶩文楷 TC、jf open 粉圓、芫荽、源泉圓體、俐方體 11 號（像素）。使用前仍請確認版本的授權檔。
- **字型檔放在專案裡，用 `@font-face` 載入，渲染時不要連外部網址**。中文字型很大，可以只取用到的字做子集。
- 渲染前確認字型已載入：引擎的字型檢查遇到缺字會直接報錯，不會默默換成系統字型（Nyankomintsu 的做法）。缺字在成品裡會變成方塊或醜的替代字，是評審的「致命缺陷」之一（mg-styles-15）。
