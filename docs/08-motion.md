# 08 動態與轉場

## 動態的原則

### 每個動作都要有意義

- **說出每個動作在解釋什麼**。DavidKPiano 整理的「一句話抽卡片」症狀裡，最後一條就是「動了但沒有意義」。
- **導演變化，不只是入場**（Hypit）：變化前是什麼、變了什麼、什麼留下來。再漂亮的入場也救不了一個沒有說明重點的靜止畫面。
- **保持物件的身分**：同一張卡片變成附件，而不是消失再出現另一張。
- **從關係推導動作**：游標移到按鈕上、徽章跟著物件、被拒絕的拖曳從它到達的地方彈回。這樣改版面時動作不會壞掉。
- **一次一個主要動作**；每個動作段落只有一個視覺中心，避免投影片式版面（OpusClip）。
- **不要原地晃**：呼吸、漂浮、緩緩飄移、光暈脈動這類持續循環，會讓人覺得「影片在等」（HyperFrames）。檢驗方法：任意暫停一秒，畫面上應該有某個有意義的東西正在移動。
- **停頓讓動作落地**（onetake）：高潮的動作與結果之間留 0.3–0.75 秒的「逗號」（HyperFrames）。

### 曲線決定重量

- 每個會動的屬性都要有刻意的曲線：位置、縮放、旋轉、透明度、遮罩、模糊、字距、容器尺寸（OpusClip）。
- **距離 × 時間 × 緩動 = 感覺到的重量**。
- 出場加速、進場減速；彈簧只在彈性有意義時使用。
- 縮放前先決定錨點：從觸發點展開。

EGSECDA 的緩動預設：

| 用途 | 曲線 |
|---|---|
| 進場 | expo-out `cubic-bezier(.16,1,.3,1)` |
| 出場 | expo-in `cubic-bezier(.7,0,.84,0)` |
| 鏡頭漂移 | sine in-out |
| 彈出 | back-out，過衝 1.4–1.7 |
| 撞擊 | 先用 85% 的時間走完 90%，最後一下吸附 |
| 手繪感 | 先緩動，再量化到 12 fps |

HyperFrames 的時間規則：單一進場 ≤ 0.8 秒；出場約為進場的 75%；整組錯開總長 ≤ 0.5 秒；不要 bounce.out、elastic.out；同類元素用同一條緩動與同樣長度。

**長運鏡不要用 `ease.inOut`**。引擎的 `ease.inOut`（`cubic-bezier(0.87, 0, 0.13, 1)`）是給短距離位移用的：中點的速度是平均的 7.7 倍，中間 20% 的時間走完 69% 的距離，頭尾各四分之一的時間加起來只走 8%。拉長到幾秒，看起來就是停住、甩一下、再停住：4 秒橫移一個畫面寬（1920 px、30 fps），平均每幀 16 px，中段卻是每幀 119 px。幾秒長的推、拉、搖改用 `ease.sineInOut`（最快是平均的 1.57 倍）或 `x => smoothstep(0, 1, x)`（1.5 倍），上表的「鏡頭漂移」用 sine in-out 就是這個原因。`track()` 預設用 `ease.inOut`，鏡頭的關鍵幀要自己傳曲線。本專案的對照實驗裡，3–13 秒長的運鏡都在中段甩了一下：逐格差異（每一格和前一格差多少）在 22.0 秒有一個高峰，鏡頭改用 `smoothstep` 之後，它掉出了前 14 名。

### 封閉式彈簧

引擎的 `spring(t, {freq, damp})` 是不需要狀態的彈簧，任何時間都能直接算（xilo 的公式）。同一類元素用同一組參數：

| 元素 | 頻率 ω | 阻尼 ζ |
|---|---|---|
| 按鈕、開關 | 22–26 | 0.75–0.85 |
| 卡片、容器、鏡頭 | 14–16 | 0.70–0.75 |
| 大字、3D、Logo | 9–11 | 0.85–1.0 |
| 吉祥物、貼紙 | 16–20 | 0.40–0.50 |

目標中途改變時，把每次改變的階躍響應加起來：`v(t) = v0 + Σ (v_i − v_{i−1}) · spring(t − t_i)`。

### 模糊

- **減速時把模糊清掉**：快速進場、較長的煞車、停在銳利的狀態。模糊跟著螢幕上的速度走並設上限；**靜止的文字永遠是銳利的**；模糊移動的那一層，不要模糊整個畫面（OpusClip）。
- **動態模糊**用子幀平均：onetake 用 180° 快門；Faker MV 在 0.35 幀的快門內取 16 個子樣本；mexicat 依每塊 32×32 區域的移動量自適應取樣（靜止約 12、一般鏡頭 36、甩鏡最多 324）。
- 動態模糊**不能跨越剪接點**，不然硬切會糊成一團。本專案的渲染器依 `cuts` 處理。
- 出場要**持續移動直到看不見**；不要把位置停住再原地淡出。

## 轉場

### 向量法則（HyperFrames）

A 場怎麼離開，決定 B 場怎麼進來：

- **同一軸、同一方向**（不要鏡像），速度相符：出場 power4.in 對應進場 power4.out，距離與時間相同。
- **剪接點落在兩邊都在動的時候**：不要先停好再切，也不要從靜止開始。
- **Z 軸是正負號**：推進＝兩邊都在變大（出場 1→1.2，進場 0.75→1）；拉遠＝兩邊都在變小（出場 1→0.8，進場 1.25→1）。最常見的錯誤是出場往後退、進場卻從小變大。
- **主流方向**：整支片一個主要方向（例如往左）。其他方向保留給特定意義：往上＝昇華或結論、往前推＝更深入同一個想法、往後拉＝抵達、爆散＝離開一個世界。
- 不要連續兩個相反方向的轉場（看起來像錯誤）；改變方向要有可見的原因（點擊、撞擊）或章節邊界。
- **載體**：眼睛跟著物件走。最好的轉場讓一個具體的物件以相符的位置與速度跨過剪接點（游標、容器、飛進槽位的標記、一組字）。交叉溶解沒有載體。
- **視線要接上**：硬切之後，觀眾的眼睛還停在上一個鏡頭的主體那裡。下一個鏡頭的主體就放在那附近，或用一個動作把眼睛帶過去；要眼睛跳到畫面另一邊去找，就斷了。剪接師 Walter Murch 把這叫 eye-trace，指觀眾注意力在畫面裡的位置和移動；在他剪接時權衡的六件事裡排第四，前面是情緒、故事、節奏。檢查方法：在 `qa` 的轉場條上比較切點前最後一格和切點後第一格，主體是不是在同一區。本專案的對照實驗就有一刀切在撞擊點上，切過去後眼睛得跳到畫面右邊才找得到東西。

本專案的 `STORYBOARD.md` 有 Out 欄位，`studio plan` 會提示沒有寫交接的鏡頭。

### 邊界要被設計（onetake）

- 每個轉場都要說出**什麼活下來**，變成下一拍：提示列 → 應用程式視窗；卡片 → 頁面。
- 一個不剪接的鏡頭：帶著主體走、甩到下一個元素落下的地方、手持般的浮動、撞擊時震一下。
- onetake 用一個分數量測「延續度」：第一版 0.00 被退，第二版 0.40 被退，第三版 0.75 通過。延續是量出來的，不是希望出來的。

規則：

- **整支片只用 2–3 種轉場，反覆使用**（HyperFrames）。
- 轉場在媒材內部發生，用一致的語法；避免預設的淡入淡出與無理由的硬切（lemo-opuscar）。
- 筆刷擦除這類明顯的轉場只用在少數章節邊界，其他地方讓動作帶動剪接（paint-mv）。

### 常見的轉場錯誤

- **忙碌的交叉溶解**：兩個複雜畫面疊在一起變成混濁的雙重曝光。改成錯開，或先退到背景色再進來（brag）。
- **長時間由亮到暗的溶接**會變灰。改成硬切或模糊出場（guizang）。
- **透明度加總小於 1 的那幾幀會閃白**：舞台要有不透明的底色（HyperFrames）。
- 在兩個鏡頭姿態之間移動攝影機，用平滑縮放路徑（van Wijk–Nuij），位置與速度都連續（Faker MV）。

## 鏡頭

- **2D 也有鏡頭**：推、拉、視差、對焦轉移、畫中框（lemo-opuscar）。全片至少 4 種不同運鏡，加上真正的景別變化；一個招牌鏡頭。
- **鏡頭只為了引導注意、揭示、跟隨而動**；一個清楚的固定畫面不需要裝飾性的推鏡（OpusClip）。另一派做法是每場戲都有 1.03–1.07 倍的緩慢推進，讓鏡頭從不完全靜止（twoclipping）。兩者不衝突：推進要有意圖。
- **只有一個世界座標到螢幕座標的函式**：任何跟著主體的特效都用它，不然鏡頭一動特效就脫離主體（lemo-opuscar）。
- 手繪層可以一拍二，但**鏡頭與光每幀都要平滑**：一跳一跳的鏡頭看起來像卡頓（lemo-opuscar）。
- **鏡頭推進一個新尺度時，那個尺度的內容排在鏡頭停住的位置，不要跟著移動中的鏡頭排**。本專案範例 song-to-mv 的資料圖從整首歌推進到兩小節，九個歌詞字一開始跟著鏡頭排，在 0.22 秒的推進裡全部擠在一起、疊在圖上；改成字先站在終點、隨章節升起，讓圖推進去對齊它們，切點那格就乾淨了。

| 運鏡 | 參數參考 |
|---|---|
| 視差 | 5–8 層：遠景 0.02–0.06、山 0.1–0.3、中景 0.35–0.6、主體 1、模糊前景 1.2–1.5（papermotion）；縮放比例 = 鏡頭縮放 ^ 深度（koldo2k） |
| 手持 | 以種子產生的微晃；平靜 2–4 px、驚慌 8–13 px（papermotion） |
| 拍點縮放 | 0.8%–3%（EGSECDA） |
| 撞擊推鏡 | 3 幀＋放射模糊（EGSECDA） |
| 大鼓震動 | 低頻能量的三次方，只用在副歌（EGSECDA） |
| 撞擊反應 | 方向性的衝擊（指數衰減 × 餘弦彈簧）＋雜訊震動（bad-time-mv） |
| 傾斜 | 荷蘭角擺動 |

拍真實感的鏡頭時，告訴它**誰拿著攝影機、坐在哪裡、怎麼移動**（abxxai）；或直接說「第一人稱遊戲視角」、「空拍機視角」，不需要專業術語也能得到自然的運鏡（卡尔的AI沃茨）。

## 動態字體

依目的選手法（OpusClip）：

| 目的 | 手法 |
|---|---|
| 介紹 | 錯開排入定位、收緊字距、整組減速 |
| 換一個詞 | 只讓變的那個詞用遮罩滾動，基線不動，寬度動畫 |
| 選出一個概念 | 讓片語依序通過同一個焦點區 |
| 從想法到行動 | 同一段文字移進輸入框 |
| 收束 | 關鍵字接力，再組成一句話，停住 |

EGSECDA 的文字食譜：依筆順書寫、逐音節彈出、巨字、直排瀑布、可變字型的字重綻放、亂碼解碼、文字砸下、殘影字、餘燼消散、拆字、卡拉 OK 填色、歌詞隧道。mexicat 讓字型的寬度軸跟著拉長的音一起變寬。

技術細節：

- 量測文字前先確定字型載入完成。
- 用遮罩「升起」的字，遮罩框要包得住整個字：框從字的格子上緣開始時，200 px 的數字頂端會被切掉約 20 px（字的上緣高過格子）。看最大的那個字的靜態圖。
- 容器形變時裡面的文字切換要有自己的進出時間（xilo、twoclipping）。
- 會被鏡頭縮放的文字不要加 `will-change`，會糊（twoclipping）。
- 中文依語意單位分組，數字和單位放在一起，不要把英文的字距與延遲照搬到中文（OpusClip）。

## 角色的表演

- **因果鏈**（HyperFrames）：點擊 → 擠壓 → 彈簧釋放 → 飛行 → 撞擊 → 反彈 → 揭示。效果從造成它的那一幀開始，反應大小和質量成正比。
- **預備 → 動作 → 過衝 → 回穩**（用阻尼餘弦）。
- 拍點上擠壓，回彈時伸展（painted-rickroll）。
- **撞擊幀**：2 幀反相剪影＋放射線；**停在高點**：畫成靜止圖再慢慢平移（lemo-opuscar 的 80 年代動畫）。
- 線條抖動 0.7–1.6 px、每秒 12 次（EGSECDA）。
- 嘴型 3–4 種、8 fps 切換；嘴型可以跟著唱的音符開合（painted-rickroll 的 `voiceMouth`）。
- 次要動作（衣襬、電線、頭髮）用彈簧或固定步長的模擬，**從預捲開始算**，所以任一幀都能重現（painted-rickroll 用 120 Hz 的 Verlet）。
- 物理要可重現：解析解、固定步長從 0 算到 t、或預先模擬好再「烘焙」成關鍵幀（bad-time-mv 的 `bake`）。

## 檢查動態

- **先測最重要的那個動作**，在短片段裡每次只改一個變數，保留可比較的版本（OpusClip）。
- 修正順序：**先簡化動作，再調曲線與剪輯，最後才加裝飾**（OpusClip）。
- 最快的動作要一幀一幀看（mg-styles-15）。
- 在**最大的動作之後那一刻**判斷：動作停下來時畫面成立嗎（Hypit）？
- 數字檢查跳動：某條線一幀移動超過 12 px 就是跳（papermotion）。
- 「一句話抽卡」的症狀與對策（DavidKPiano）：

| 症狀 | 對策 |
|---|---|
| 太快 | 放慢到 0.7 倍，關鍵文字至少停 1 秒 |
| 效果太多 | 禁用清單 |
| 沒有整體感 | 每場一個運動軸，或一鏡到底 |
| 沒有焦點 | 說出焦點是什麼並推近它 |
| 每個緩動都一樣 | 彈簧加上不同的時間 |
| 沒有編排 | 節拍網格，每拍一個變化 |
| 動了沒有意義 | 說出每個動作在解釋什麼 |
