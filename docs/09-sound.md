# 09 聲音設計與混音

幾乎每一支高播放作品被批評最多的都是聲音：

- plotome 的 46 分鐘片：「BGM 和音效讓我焦慮」。
- mattshumer 的遊戲 demo（19.6 萬觀看）：回覆幾乎都在說「聲音像靜電雜訊」。
- CaCATions：Opus 合成的音效「塑膠感、廉價」，最後改用遊戲本身的音效。
- Vibe 知識類：「同一首 BGM 一響我就退出」、「賽博催眠」。

代理**聽不到聲音**。這一章的重點是：怎麼在聽不到的情況下仍然把聲音做對，以及哪裡一定要人來聽。

## 音樂從哪裡來

私下練習用任何歌都可以；要公開的片，音樂的授權和音樂庫比較見 [13](13-rights.md#歌曲)。

### 程式合成音樂要避開的陷阱

- **指定曲風與樂器**。不指定時 Opus 很愛 FM 合成，結果就是一聽就知道是 Opus 做的。
- 純正弦波很單薄：加泛音、微走音、殘響（xilo）。
- 低頻平衡：20–120 Hz 比其他頻段低約 3 dB；pad 不要低於 MIDI 48；貝斯加二、三次泛音，小喇叭才聽得到（lemo-opuscar）。
- 管弦與鋼琴合成不出來，用 CC0 取樣音色代替：VCSL、FreePats、VSCO 2 CE、Salamander 鋼琴（lemo-opuscar、mg-styles-15、kevin_t_ngo 都用過）。
- 本專案的 `tools/py/music.py` 只是**示範與練習用**的版權乾淨音樂產生器；正式作品請用真正的音樂。

## 音效

### 每個聲音都要有理由（Hypit）

- 先聽素材本身已經有什麼，再決定要加什麼。
- 每個加上的聲音都要有表達上的理由。
- **每次剪接都放同一個音效，很快就會讓人疲乏**；刻意的安靜也是表達。
- 一個畫面的剪接不一定要切斷聲音的世界：環境音、把蒙太奇串起來的音樂都可以跨過剪接。

### 掛在事件上

- 音效**屬於某個事件**：一個字被唱出、一個元件被點擊、一個物件落地。
- 畫面上每個看得見的動作都要有聲音，而且符合材質；分三層：環境、擬音、音樂（lemo-opuscar）。
- 高潮或轉折前至少 2 次真正的靜默；靜默後的第一個聲音是全片最重要的聲音之一（lemo-opuscar）。
- 聲音可以當轉場（J-cut／L-cut：聲音比畫面早到或晚走），至少用兩次。

### 特徵點：音效要對的不是檔案開頭

一個音效檔裡「聽起來的那一下」不在第 0 秒。guizang 的同步公式：

```
音效開始時間 + 特徵點偏移 = 鏡頭開始時間 + 動作時間
```

| 音效 | 特徵點 |
|---|---|
| 點擊、碰撞、單發音效 | 起音 |
| 呼嘯（whoosh） | 經過的峰值 |
| 上升音（riser）、反轉鈸、蓄力 | **結尾**（要在動作那一刻結束） |
| 撞擊 | 峰值 |

本專案的 `tools/py/sfx.py` 產生的每個音效都附有特徵點資料，`mix.py` 會自動扣掉偏移。

brag 的細節：進場的「啵」放在第一個看得見的幀之前 0–0.1 秒；成功的「叮」放在數字完全出現時；一排錯開出現的元素只替第一個、最後一個、最強的一個配音效。

### 不要太密

- 頻繁的音效要去彈跳（≥ 0.09 秒）：papermotion 把 477 個腳步聲減到 110 個。
- 依時間觸發的音效，在「跨過」那一刻觸發（上一幀 < T ≤ 這一幀），不要每幀判斷一次。
- 撞擊那一刻可以讓音樂整個退掉。

### 程式合成音效的配方

papermotion 的配方（數字可以直接用，本專案的 `sfx.py` 以它們為起點自己實作）：

| 音效 | 配方 |
|---|---|
| 雪地腳步 | 約 2.3 kHz 的帶通雜訊＋細碎爆裂 |
| 撞擊 | 150→40 Hz 的正弦重擊＋一聲短促的喀＋低通雜訊掃頻 |
| 呼嘯 | 250 Hz→2.5 kHz 的帶通掃頻 |
| 「聲音」嗶嗶 | 三角波滑音 60–250 毫秒 |
| 亮晶晶的鈴 | FM，比例 7.1 |
| 音樂盒 | FM，比例 4，指數 1.3 |
| 撥弦 | Karplus–Strong |
| Pad | 三個鋸齒波，±14 音分，低通 850 Hz |

接觸時發出的音符走五聲音階，永遠和諧。

合成音效的品質上限有限。CaCATions 改用遊戲原聲、iamroody 請另一個 AI 聽過再修（筆聲太尖、翻頁太弱、少了數數的聲音），都是好做法。

## 混音

`studio mix` 收集片子每一鏡的 `sfx` 和 `data/sfx.json`，依特徵點放好、依角色壓低音樂、把響度正規化。整支片在別的工具做時（[10](10-render.md#整支片在別的工具做)），音效全部寫在 `data/sfx.json`（`{ "sfx": [{ "t": 12.5, "sound": "whoosh", "sync": "peak", "why": "門打開" }] }`，`t` 是那支影片的秒數）。

### 依角色壓低音樂（ducking）

guizang 的確定性壓低表。重疊時取**最深的那個**，不要相加：

| 角色 | 壓低 | 起始／保持／釋放 |
|---|---|---|
| 點擊、開關、彈出 | 3–3.5 dB | 40／100–120／200–240 毫秒 |
| 打字 | 2.5 dB | 40／350／250 毫秒 |
| 轉場 | 4 dB | 40／160–200／300–350 毫秒 |
| 完成、通知 | 5–6 dB | 40／350–450／350–400 毫秒 |
| 品牌結尾 | 5 dB | 40／550／450 毫秒 |

有旁白時，人聲大約比音樂高 10 dB；TTS 的峰均比高，先壓縮人聲再平衡（lemo-opuscar）。

### 響度

| 項目 | 目標 |
|---|---|
| 整體響度 | −14 LUFS（串流平台的標準）；papermotion 用 −16 |
| 真峰值 | ≤ −1 dBTP（AAC 編碼後要再量一次） |
| 量測 | ffmpeg `loudnorm` 兩階段：先量，再用量到的值正規化 |

- **最大的故事時刻要是最大聲的**（在波形圖上確認）。
- 立體聲要能轉單聲道：手機常常是單聲道播放，不要用 Haas 效果加寬，立體聲相關係數維持在 0.3 以上（mg-styles-15）。
- ffmpeg `ebur128` 的報告要讀 `Summary:` 後面那一段；前幾行的 −70 是暖機值（papermotion）。
- 音樂比影片長超過 1 秒要警告；影片比音樂長時用靜音補齊（`apad`），不要用 `-shortest` 把片尾切掉。

## 沒有耳朵時怎麼檢查聲音

「模型聽不到，就看圖」（xilo）。本專案的 `qa` 會產生：

| 證據 | 看什麼 |
|---|---|
| 響度報告 | 整體響度、真峰值、響度範圍 |
| 波形圖 | 削波、意外的靜音、最大聲是不是在高潮 |
| 頻譜圖 | 持續的低頻轟鳴、刺耳的高頻、空掉的頻段 |
| 音效清單 | 每個音效和它的動作差幾幀、和最近的拍點差幾幀（**只報告，不默默移動**，guizang） |
| 音畫同步 | 成品音軌和原曲的起音曲線互相關，報告偏移毫秒 |

更進一步：

- aj_dev_smith 把波形匯出成 PNG，混音時看著圖調整；用語音辨識模型檢查合成的歌聲是不是聽得懂。
- 交付時用 lemo-opuscar 的做法：每一行聲音設計表在混音裡都存在。
- **請另一個能聽音訊的模型聽**：plotome、iamroody、南辰燏炚都這樣做。
- **誠實交接**：Tz_2022 的代理在交付時寫「我聽不到；我檢查了音量與削波；時間軸與字幕共用一個資料來源，應該是同步的；請聽一次」。這是最好的交接範本。

聽的順序：音效分軌 → 混音主檔 → 最終 MP4（guizang）。**最後一步永遠是人戴耳機聽完整支成品**。

## 旁白（選用）

- 不指定時，Claude 會用免費的 edge-tts，那種「AI 腔」一聽就出戲。**一定要指定旁白引擎**（阿珍）。
- 選 TTS 的三個條件（plotome）：多次生成音色固定、可以商用、有**逐字時間戳**（沒有就用語音辨識事後對齊；逐句對齊通常就夠）。
- 腳本凍結後才錄旁白；旁白是時鐘，畫面跟著旁白走（見 [04](04-music-timing.md)）。
- 數字在 TTS 文字裡寫成國字或英文單字，字幕裡用阿拉伯數字（lemo-opuscar）。
- 不認得的唸法不要猜，問人並用耳朵比較 A／B（HyperFrames）。
- 聲音複製需要本人同意；開源權重的語音模型不一定能商用（plotome 的風險表）。
- 金鑰放 `.env`，不要貼進對話（見 [02](02-setup.md#密鑰與權限)）。
