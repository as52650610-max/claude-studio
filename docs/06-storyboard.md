# 06 企劃與分鏡

技術問題 Opus 自己會解決；「這支片到底在說什麼」要你和它一起想清楚。高播放但低收藏、或被罵「像作品集」的作品，問題幾乎都出在這一章。

## 先找一個核心概念

一句話說得完、而且每個畫面都在為它服務的想法。從高收藏作品歸納出的幾種找法：

| 方法 | 例子 |
|---|---|
| **把整支片變成一個隱喻** | 「整支片就是一段對話：『我』是擬人化的 Claude，『你』是沒有臉的使用者」（Nyankomintsu）；「唱歌的『我』是一隻從進度報告剪下來的紙老鼠」（アルジャーノン） |
| **用媒材本身的語法說故事** | bad-time-mv 用 Undertale 的戰鬥介面講故事：MERCY 被刪掉、愛心把戰鬥框推到 FIGHT 上，最後**剪掉按鈕本身** |
| **歌詞對應真實現象** | 穆阿蒂布把每句歌詞對應到真的數學或電腦現象：開機是電路走線、副歌是 GPT-2 真實的注意力頭、關機是開機程序倒著播 |
| **觀眾本來就在用的語言** | Pdoom 動畫版把 Claude 畫成 90 年代動畫的偶像，因為「福音戰士本來就是那群人談論 AI 的方式」 |
| **一條線串起時間** | Apple 50 年「一條線與光畫出 50 年」；留言說這比堆產品鏡頭好 |
| **大歷史接到一個轉折** | 《魚》：3.75 億年前一條魚撐上泥灘 → 兩次世界大戰 → 「演化沒教我們放下武器，這一步要自己走」 |

不要只照字面畫歌詞（doubleunplussed 的提示直接寫「不要逐字圖解歌詞」）。《達拉崩吧》AI 版被批評的地方是：原版 MV 用撲克牌、紙和垃圾桶就講完故事，便宜又洗腦；AI 版元素很多，卻沒抓到那股荒謬的老 B 站味。**抓住歌的精神，不是堆元素**。

情緒也要對。《バカみたいに》的原曲是憂鬱、反覆的折磨，AI 版卻「太花太積極」。留言建議在提示裡寫清楚情緒基調，並給參考靜態圖。

## TREATMENT.md：導演的答案

用導演的語言寫，不寫套件名稱與建置順序（Hypit 的規則）。範本在 [`templates/common/TREATMENT.md`](../templates/common/TREATMENT.md)。

アルジャーノン 的說明欄就是一份很好的導演陳述：概念、角色的意義（名字、眼睛＝視覺、手＝工具、心＝不確定）、結尾的畫面（四季輪轉，小墳上每季多一朵花，立體書闔上變成空白頁：「空白不是失去，是可以再寫一次」）。

## 克制與高潮

**克制預算**（EGSECDA 特效食譜）：

- 選 3–5 個主母題，每個只有一個意義；每鏡最多 3 個。
- 高潮以外，每鏡最多 1 個全畫面效果＋1 個裝飾。
- 顆粒、紙紋這類質感一直開著，當作黏合劑。
- 每段逐步升級。
- 全片至少 3 次完整的停頓（2 小節以上）。
- 轉場從場景內部發生。
- 用一個想法結束，不要用淡出結束。

**高潮的規則**（Nyankomintsu）：

- 破壞感和強光不要在同一幀達到頂點：前半段破壞，後半段光明。
- 每個關鍵字都比上一個大。
- 完整的圖像留到最後一幀才出現。
- **最後一幀先做成靜態圖並核准，再做朝它前進的動畫**。它應該是高潮開始後唯一乾淨、靜止、對齊的畫面，停留至少 1.2 秒。

**結尾不能趕**。废才俱乐部的短劇結尾改了六版：在最亮的一幀硬切黑太突兀 → 改成一個連續推門＋關門聲 → 最後延長金光再淡出。「結尾要留時間讓人回味。」bad-time-mv 的結尾是一個問句加上音樂結束後 4 秒的靜默。

## 短片的故事結構

lemo-opuscar 的導演規則：

- 一個主角、一個目標、一個轉折。
- 前 3 秒就要有鉤子，不要慢慢浮現 Logo。
- 結尾要呼應：首尾相同、拉遠揭示規模、或「第二次做對了」。
- 情緒最高點用一個這種媒材獨有的招式。
- 刪掉多餘的：「一個在縮圖大小就看得懂的笑點，勝過三個看不懂的」。

makevoid 的**升級回呼**：鉤子介紹一個道具 → 主歌誤用它 → 落拍時它變形 → 結尾回收。配上背景笑點、比例變化、圖解笑話、假介面、匹配剪接、角色反應，再留幾個安靜的拍子：「混亂來自編排，不是一直隨機閃爍」。

**注意力裝置**（Pdoom 動畫版）：

- 第一幀就是全螢幕歌詞疊在角色眼中的火花上。
- 一個會隨歌曲升級的 HUD：年份計數器越跑越快（每小節一個月 → 每拍一年 → 20XX → ∞），末日機率表 8 → 34 → 61 → 86 → 99.9 → ERR。
- 每次副歌重複同一個招牌動作。
- 歌詞有三種尺寸模式：全螢幕、側邊、字幕。
- 段落之間的標題卡在縮圖大小也讀得懂。

## 歌詞轉畫面的方法

言炎的六步裡最關鍵的一步：**每句歌詞寫下情緒、文字動作、鏡頭運動、和前後句的連結**；關鍵動作綁在特定的字與拍上；轉場一起設計：上一鏡留下什麼，下一鏡把它變成什麼；用新的方式重用同一個元素來縫合場景。

實際操作：

1. 把歌詞一句一句列出來，每句標上段落與時間。
2. 能直接對應的句子，給一個具體、可以截圖的畫面（makevoid：「每句歌詞都要有自己能截圖的視覺笑點」）。
3. 不能直接對應的句子，用抽象意象或母題的變化。
4. 每句寫一個動詞：這一鏡裡誰做了什麼。
5. 標出關鍵字，關鍵字是那一句的視覺高點。
6. 寫 Out 欄位。

需要細節時做研究：makevoid 的做法是搜尋歌曲主題與歌詞片語，寫進 `RESEARCH.md`（來源、網址、日期、事實或靈感、視覺笑點、用在哪一鏡、是否虛構）。

## 分鏡表

格式見 [03](03-workflow.md#g3-分鏡)。補充的規則（paint-mv、lemo-opuscar）：

- **場景不是卡片**：每一章一個地點；副歌的「主場景」每次回來都升級。
- 角色從歌詞來：1–2 個主角，變體當配角，每段主歌一個客串。
- 有動機的轉場：只在少數章節邊界用筆刷擦除；其他地方讓動作帶動剪接（嘴巴閉上變黑、潛入眼睛、泡泡破掉、閃光）。
- 情緒變化用形變，不要硬切臉。
- 鏡頭一直在動；每章有自己的色彩弧線。
- 副歌時主角約占畫面高度 40%。
- 字少：幾個大大的狀聲詞，不要標籤，不要歌詞看板。
- 混合路線加一欄「來源」：`SD`（影片模型底片）／`IMG`（靜態圖＋視差）／`JS`（純程式動態）。

**段落表**（bad-time-mv）適合在分鏡表之前先做：

| 小節 | 時間 | 音樂 | 畫面 |
|---|---|---|---|
| 1–8 | 0:00–0:16 | 前奏，只有貝斯 | 黑底，一顆心跳動，每小節第一拍亮一下 |

## 參考作品的拆解（ANALYSIS.md）

有參考影片時，先拆解再企劃。**只學語法，不抄畫面**。

**取樣方法**（plotome，「Claude 不能看影片，只能看圖」）：

1. 每 10 秒左右取一幀，加上字幕，看整體。
2. 計算相鄰幀差異，在**變化最快的段落密集取樣**。
3. 在**彈幕最密的地方**取樣：那是觀眾反應最大的時刻。

然後請代理說出它看到的技巧：「引導物件」（一個小光點帶眼睛進下一場）、「巢狀拉遠」（上一場縮成下一場的一個元件）、剪輯節奏、哪裡停頓留白。

**拆解表**（makevoid）：

| 幀範圍 | 歌詞／音訊 | 鏡頭 | 角色動作 | 圖形與路徑 | 前景／背景 | 可重用的語法 |
|---|---|---|---|---|---|---|

**用數字拆解**（onetake）：靜止占多少、在哪裡剪、動作怎麼加減速。

**分清事實與解讀**（Hypit、路北路陈）：「這個邊緣在畫面裡往下移」是觀察；「卡片往下移」是解讀（也可能是鏡頭在動）。路北路陈大部分的返工都來自把兩者混在一起。另外，取樣只能證明「取樣的時間點有什麼」，中間的短暫事件可能被漏掉。

## 知識科普的腳本

Vibe 知識類是 Opus 動畫目前觸及最廣的類型（比特新语兩週約 50 萬粉絲、單支最高 420 萬播放）。

### 腳本解剖（比特新语的說明欄就是腳本）

1. **第二人稱的日常痛點**：「差 3 秒沒趕上的地鐵，差 1 分的分數線……」
2. **一個精確的歷史研究或實驗**，有年份、人名、數字：Axelrod 1980 年的比賽（15 種策略、120 場、24,000 回合）。
3. **反直覺的結果**：一直背叛的策略墊底，四行程式的「以牙還牙」贏了。
4. **補充與複雜化**：誤會會讓以牙還牙永遠互相報復 → 大約三分之一的時候要原諒。
5. **落到觀眾生活的一句話**：「先伸出手，但別忘了，你有牙。」
6. **獻詞**：「致所有還在觀察期的人」。
7. **誠實註記**：畫面中的數據來自真實模擬；完整引用；「僅作示意」。

### 讓播放差十倍的四件事（汤姆CC）

1. **鉤子**：第一秒是一個驚人的畫面加一個視覺錨點（滿版的山、很小的人、其中一個穿紅衣）。第一句文案要跟觀眾有關，不是術語或歷史。
2. **節奏**：字幕在小節線上切換；強拍前半句、強拍爆發（見 [04](04-music-timing.md#蓄力與爆發)）。
3. **一個每個人都能回答的問題**：409 則留言 vs 8 則。
4. **無縫轉場**：一個元素帶到下一場，整支片像一鏡到底。

### 模擬那個主張

算法之外的每支片都是：Opus 寫模擬程式 → 結果存成 JSON → 動畫讀 JSON，所以**畫面上每個數字都是真的** → 說明欄引用論文並寫「我們照原文規則重寫重跑」。這直接回應了這類影片最常見的批評（淺、無法驗證）。DotCSV 的像素動畫裡，Opus 主動訓練了一個真的 MNIST 網路，讓動畫嚴謹。

同時要誠實說明範圍：算法之外「考試最後一分鐘改答案」被留言質疑方法（改掉已知錯誤和猜測混在一起）；「臨界點」被指出把特定模型的數字套到別的現象上。**類比要標明是類比，模型的假設要說出來**。

### 其他規則

- **每一段回答讀者看完上一段最自然的下一個問題**（plotome）。
- **一句話一個畫面**：「沒有聲音看不懂，就重做」（Lucas_IA_）。
- 每個知識點都要想好怎麼變成畫面，不然就像全是字的投影片（Git源宝）。
- 先看意思，再看美感；常見修正是把 3D 改成 2D、或把鏡頭推進某個物件（plotome）。
- 加一道**事實查核**：风之谷AI 的星艦片被指出「星艦不是飛向月球」。
- 刪掉 AI 文案味：「不是……而是……」、「說白了」、「穩穩地接住你」、連串破折號。留言說「開口就是『不是……而是……』，點開就退出」。
- 道德昇華要有證據撐住，不然就不要做。留言批評「邏輯推理反而給情緒讓路」。

plotome 拆解一個快速成長帳號得到的**短片配方**：前 2 秒是一個具體的人加一個異常的時刻；一支片一個概念；2–3 個逐步升級的數字；每 2–3 秒一行字幕；沒有旁白；一條環境音軌。

## 短劇與 AI 混合路線的劇本限制

用影片模型拍攝時，劇本要配合模型的能力（ai_dvd6 的規則）：

- 最多 2 個角色、1–2 個場景、6–8 鏡、每鏡 3–6 秒。
- 前 3 秒有衝突，8 秒內給出繼續看的理由，中段升級，最後 8–10 秒反轉。
- 避免：人群、打鬥、長段對嘴台詞、換裝、複雜的手部與物件互動。

废才俱乐部用 Opus 當導演做短劇時，先寫三份文件再寫任何生成提示：**定稿劇本**（台詞不動，只補拍攝方式）、**分段表**（一段＝一次生成，兼做進度表）、**連戲表**（身分記號如右眼下的痣、每場戲的道具狀態、誰站哪裡面向哪裡、所有畫面文字、時間與天氣）。
