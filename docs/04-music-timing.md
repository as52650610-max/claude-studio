# 04 音樂分析與節拍

畫面的時間要從音樂量出來。十元钱钱的作者拆解 Opus 卡點的過程後說：「AI 沒有聽音樂，它在算數學。」這不是缺點，前提是數學算對了，而且有人用耳朵確認過。

## 節拍地圖（songmap）

`node tools/studio.mjs analyze projects/my-mv` 讀 `audio/` 裡的歌曲，輸出 `data/songmap.json`。全片所有時間都從這份檔案來。

| 欄位 | 內容 | 用途 |
|---|---|---|
| `bpm`、`tempo` | 速度、信心分數、其他候選速度、是否有歧義 | 決定剪輯節奏 |
| `beats` | 每一拍的時間（秒） | 小動作、狀態變化 |
| `downbeats`、`beatsPerBar` | 每小節第一拍、每小節幾拍 | 切鏡、大變化 |
| `phase` | 強拍位置的信心與其他候選 | 檢查強拍有沒有差半拍 |
| `drift` | 每 32 拍的累積偏差（毫秒） | 偵測速度會飄的歌 |
| `sections` | 段落（起訖、能量、相似段落標籤） | 章節切分、能量曲線 |
| `stops` | 音樂突然停住的片段 | 定格、靜音、反差 |
| `impacts` | 特別強的重擊 | 高潮動作、轉場 |
| `events` | kick／snare／hat／人聲起音，每個附強度 | 鼓點反應、歌詞校正 |
| `envelopes` | 每秒 60 格的能量曲線：整體、低頻、中頻、高頻、起音 | 亮度、粒子量、鏡頭震動的強度 |
| `warnings` | 歧義和量測對不上的地方，每條都寫了下一步怎麼做 | G1 逐條處理 |
| `notes` | 分析器為了讓自己的量測一致而改過的地方，例如把段落邊界移到停拍後那一小節；用 `--sections` 指定段落時，記下指定的小節和分析器自己會放在哪裡 | 聽點擊預覽時對照 |

在頁面裡，引擎把它包成簡單的函式（見 [10](10-render.md) 與 `engine/README.md`）：

```js
song.beatAt(t)          // 現在是第幾拍（含小數）
song.barAt(t)           // 第幾小節
song.T(17, 1)           // 第 17 小節第 1 拍的時間（秒）
song.T(17, 3, 2)        // 第 17 小節第 3 拍的第 2 個十六分音符
song.section(t)         // 現在在哪個段落
song.env('low', t)      // 低頻能量 0–1
song.hit('kick', t, 0.12) // 最近一次大鼓的衰減脈衝 0–1，半衰期 0.12 秒
```

## 分析流程

本專案的 `tools/py/analyze_song.py` 只用 numpy、scipy 與 ffmpeg，不需要安裝 librosa 或深度學習模型。步驟：

1. 解碼成單聲道，計算短時傅立葉轉換。
2. **起音包絡**：對數頻帶的頻譜通量（spectral flux），代表「新聲音出現的強度」。
3. **速度候選**：自相關找週期，乘上以 120 BPM 為中心的先驗分布；列出所有接近的候選。
4. **節拍追蹤**：動態規劃找出最符合起音、又最接近固定間隔的拍點序列，再對齊到附近的實際起音。
5. **強拍相位**：低頻（大鼓）通常落在 1、3 拍，中頻（小鼓）落在 2、4 拍，和弦變化通常在小節開頭。把四種相位都打分。
6. **段落**：以小節為單位計算自相似矩陣，用新奇度曲線找段落邊界，再把相似段落標同一個字母（A、B、A′）。接著和自己量到的停拍、大重擊對齊：停拍後樂團回來的那一小節、或大重擊落下的那一小節，旁邊一小節內有邊界就移過去；停拍後最近的邊界在兩小節以外，就從那裡開一個新段落。移過和新開的邊界寫進 `notes`；停拍或重擊不在小節線上、或落在段落中間的，回報 SECTION MISMATCH。用 `--sections` 指定的段落照用、不移動（見下面的點擊預覽）。
7. **事件**：停頓、重擊、大鼓、小鼓、腳踏鈸、人聲頻帶（300–3400 Hz）起音。大鼓要留下低頻：起音後 30–100 毫秒，40–90 Hz 的平均音量要在全曲這個頻帶高點（第 95 百分位）的 24 dB 以內，不然是漏進來的小鼓（3/4 拍的歌最常見）。分離的人聲軌上，比前 2 秒峰值低 20 dB 以上的起音是殘響或回音的尾巴，強度低於 0.12 的是長音裡的抖動，都不算。
8. **漂移**：每 32 拍比較一次實際起音和固定網格的差距，超過 45 毫秒就警告。

這個分析器有**合成歌曲的標準答案測試**：`tools/py/music.py` 能產生已知每一拍位置的測試歌曲，分析器必須在那上面通過才算可信。這是從一位做怪物動畫工具的作者學來的：工具要先在已知答案的資料上驗證，才能拿來用。測試歌也包括有停拍、附分軌的 3/4 拍歌：段落邊界、大鼓和人聲起音都要和標準答案對得上。

## 歧義：工具要報告，不能默默選

真實的歌常常有歧義。好的工具會**說出來**（paint-mv 的做法）：

| 歧義 | 症狀 | 怎麼解決 |
|---|---|---|
| **AMBIGUOUS TEMPO 2:1** | 64 和 128 BPM 分數差不多 | 聽點擊預覽：拍子太密還是太疏？用 `--bpm 128` 指定 |
| **AMBIGUOUS TEMPO 3:2** | 三連音感或 6/8 拍 | 確認拍號，用 `--beats-per-bar 3` 或 `6` |
| **AMBIGUOUS PHASE** | 強拍可能差半拍或一拍 | 聽點擊預覽的重音位置；用 `--first-downbeat 1.234` 指定 |
| **DRIFT** | 速度漸快漸慢、現場錄音、自由節奏 | 分段手動標時間；或用 `tools/lyric-tapper.html` 點拍 |
| **SECTION MISMATCH** | 停拍結束或大重擊不在小節線上，或落在段落中間，沒有段落能從那裡開始 | 去聽那個位置。強拍判斷錯了的話，點擊預覽裡標第一拍的高音也會跟著錯，用 `--first-downbeat` 指定；是弱起，寫進 `cues.json`；段落真的從那裡開始，把那一小節加進 `--sections` 重跑 |

**點擊預覽**是 G1 的核心。`analyze` 會輸出 `qa/click_preview.wav`：原曲疊上節拍器，小節第一拍音高較高，每個段落開頭再響一聲約半秒的鈴聲。戴耳機聽完整首（或至少每個段落的開頭）。在一首真實歌曲上，paint-mv 的工具量出來和手動標的值差了 37 毫秒；這種差距耳朵聽得出來，眼睛看波形看不出來。

鈴聲落在錯的小節，就是段落開頭錯了。在生成的測試歌上，沒有停拍或重擊可以對齊的段落邊界常差一到兩小節，短歌前段的邊界也常漏掉。`analyze` 的輸出會列出每個段落從第幾小節、第幾秒開始（例如 `B bar 5 (8.51 s)`）。把聽到的段落開頭換成小節號（數高音，第一個高音是第 1 小節），用 `--sections 1,5,13,17` 重跑。指定的小節照用，`notes` 會記下來，也列出分析器自己會放在哪裡。提示不會存進 `studio.json`：之後重跑 `analyze`，`--sections`（和 `--bpm` 等）要再給一次。

## 卡點的技巧

收集自 EGSECDA 的特效食譜、Nyankomintsu、汤姆CC、netsu-ijou、lemo-opuscar 與 brag。

### 層級：誰是主角

- **人聲是主事件**，鼓點只負責預備與餘震（Nyankomintsu）。
- 不要對腳踏鈸做反應。每個 hi-hat 都閃一下是最常見的反模式（EGSECDA）。
- 「一個動作、一個聲音、一次剪接，但不要每一拍都剪」（lemo-opuscar）。

### 時間點

| 事件 | 放在哪裡 |
|---|---|
| 切鏡 | 拍點那一幀，或提早一幀 |
| 閃光 | 拍點那一幀 |
| 歌詞出現 | 開唱前 0.1–0.2 秒 |
| 筆畫書寫動畫 | 在開唱那一刻寫完 |
| 副歌主視覺 | 小節第一拍 |
| 段落切換、亮度變化 | 音樂爆發點（通常比第一句歌詞早約一拍），歌詞維持自己的時間（netsu-ijou 的實測） |
| 狀態變化 | 拍點；大變化放在小節第一拍；音效放在重擊（xilo） |

### 蓄力與爆發

汤姆CC 分析爆款時發現的節奏手法：

1. 強拍前 2–3 秒，字幕**故意只說半句**。
2. 畫面收縮、變暗，讓音樂「吸一口氣」。
3. 強拍那一幀：大字補完整句、畫面炸開、低頻重擊音效，三者同一幀。

視覺、文字、音樂的高潮落在同一幀，觀眾會感覺到「對上了」。

### 剪輯密度跟著能量走

- 副歌鏡頭 0.9–2 秒，主歌 2.5–5 秒（EGSECDA）。
- 剪輯速度跟著能量曲線走（Pdoom 動畫版）。
- netsu-ijou 的三層速度：衝刺段半拍一剪、重複段四分之一拍；一般段一拍一剪；獨白段 2–8 拍、用推鏡代替剪接。

### 動畫的節奏

- 手繪層「一拍二」（12 fps）或「一拍三」（8 fps），鏡頭、光線、粒子、顆粒維持全速。副歌強拍那一刻把手繪層切回全速，動作會「打開」（EGSECDA）。
- **亮度是棘輪**：在一個鏡頭裡只升不降，只在剪接時下降；不要跟著鼓點一明一暗（Nyankomintsu）。
- 舞蹈與動作寫成**拍數的函式**：painted-rickroll 的 Rick Astley 每一拍重心轉換、膝蓋正好在拍點下沉，並帶有預備動作與過衝。
- 用排程取代物理模擬：泡椒肥汤圆 的骨牌每一塊倒下的時間都事先排在鼓點上，所以每一下碰撞都落在拍上；整排往後挪半拍也不用重新模擬。

### 對齊的容許範圍

brag 的規則很實用：

- 重要的揭示可以往強音點移動最多 ±0.15 秒；小的入場最多 ±0.10 秒。
- 15–25 秒的片子只鎖 1–3 個強音點。
- 會傷害閱讀的時候就不要硬對。

## 時間定址：不要寫死秒數

鏡頭程式裡**永遠不要出現 `if (t > 41.58)` 這種數字**。歌詞時間重新校正、或改用另一個版本的音檔時，寫死的數字全部會錯。

用引擎的定址函式：

```js
song.T(33, 1)                       // 第 33 小節第 1 拍
at.lyric('就在這裡')                 // 這句歌詞開始前的最後一拍
at.lyric('就在這裡', { nth: 2 })     // 第二次出現的那一句
at.afterLine('就在這裡')             // 這句唱完後最近的強拍
at.cue('glass-break')               // cues.json 裡人工校正過的時間點
```

`at.lyric` 是**依歌詞內容**找時間（mexicat P(doom) MV 的做法）。歌詞重新對齊後，鏡頭會自己跟著移動。

歌的最後一拍之後，`song.T` 用最後幾拍的間隔繼續往後數：16 小節的歌，`song.T(17)` 就是音樂停下的那條小節線，適合放片尾卡。
品管與混音報告也用同樣的算法量「離拍幾格」，所以放在那裡的切點與音效會算在拍上（分析出的拍子清單在最後一拍就結束了）。

## 同步的旋鈕

- `cues.json`：所有不在拍點上的時間，一行一個，附來源（`measured`／`analysis`／`ear`／`initial`）。人耳校正只改這個檔案。
- 全域 `offset` 與歌詞 `lyricOffset`：整體提早或延後。
- 預覽頁的 `?lat=0.03`：校正你電腦的播放延遲（只影響預覽，不影響輸出）。
- 輸出後用 `qa` 檢查音畫同步：比對成品音軌和原曲的起音曲線，報告偏移量。

## 沒有現成歌曲時

- **先寫節拍器**：amy师婧拆解產品發表片的做法是先寫 `timing.json`（BPM、小節、停頓、每一拍發生什麼、情緒曲線），音樂和畫面都綁在這份「合約」上，就像前後端共用同一個 API。
- **程式產生示範音樂**：`tools/py/music.py` 依段落計畫合成鼓、貝斯、和弦、旋律，版權乾淨，適合練習與範例。要公開的作品用有授權的音樂（見 [13](13-rights.md#歌曲)）。
- **有旁白時，旁白就是時鐘**：先定稿、再錄旁白，以旁白的逐字時間戳為準排畫面（Austerlitz、plotome、Lucas_IA_ 的做法）。旁白改一句，後面的動畫都要動，所以**旁白錄音前一定要凍結腳本**。
