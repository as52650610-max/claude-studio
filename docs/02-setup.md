# 02 環境與模型設定

## 在哪裡跑

| 方式 | 優點 | 缺點 |
|---|---|---|
| Claude Code 本機（桌面版 Code 分頁或終端機 CLI） | 看得到所有檔案與版本、可用 GPU 渲染、可長時間執行 | 要自己準備環境 |
| Claude Code 雲端 | 方便、免安裝 | 上傳大小有限、版本管理弱，結束後要記得請它匯出全部檔案（SeASnAkEss） |

建議用本機。在**專案資料夾**裡啟動 Claude Code，不要在家目錄或桌面啟動。

## 模型與 effort

官方事實（Anthropic 文件，2026 年 10 月）：

- 模型 ID：`claude-opus-5-5`，2026-09-22 發布，1M 上下文、128K 輸出。
- effort 有五級：`low`／`medium`／`high`／`xhigh`／`max`。**預設是 medium**（比 Opus 5 低一級，要高品質請明確設定）。
- Opus 5.5 的思考（thinking）無法關閉，effort 是唯一的控制。

社群經驗（非官方，供參考）：

| effort | 適合 | 來源 |
|---|---|---|
| low | 下載、轉檔、拆解參考影片這類簡單雜事 | 阿珍 |
| medium | 快速試做、模板變體；言说新事做音符跳動示範第一版只花 18 分鐘 | 言说新事 |
| high | 大多數任務夠用 | 阿珍 |
| xhigh | 正式製作；留言實測「明顯比 high 好」 | 言炎影片留言 |
| max | 質的跳躍，但又貴又慢 | 同上 |

PDoomVideo（2,510 星）的過程很有代表性：第一輪 effort medium 得到簡單版本，第二輪 xhigh 跑了 45 分鐘得到成品。

**關於「ultracode」**：社群用這個名稱指 Claude Code 裡「xhigh 推理＋自動調度子代理的工作流」模式，《千本櫻》《三千年夜》《達拉崩吧》的作者都提到過。這不是 Opus 5.5 官方發布文所列的 effort 等級，名稱與行為以你所用的 Claude Code 版本為準。它會大量平行展開子代理、消耗很多 token：只在多段落的大型製作、而且有預算上限時使用，不要拿來探索。

官方價格與真實案例的花費見 [14 成本與時間參考](14-cost.md)。

## 省 token 的規則

Opus 做影片的 token 有 95% 以上是**快取讀取**，所以快取命中率決定成本。阿珍整理的規則（社群經驗，與官方快取機制一致）：

1. 一個任務一個對話。
2. 永遠在專案資料夾裡啟動代理。
3. 把背景與規則寫在 `CLAUDE.md`：固定的前綴最容易命中快取。
4. 換任務就 `/clear`；趁快取還熱時提早 `/compact`；對話中途不要換模型或設定。
5. 依任務選模型：下載、連線測試這類雜事用便宜的模型或低 effort。
6. 不要把巨大的檔案或日誌整個丟進對話；關掉用不到的工具與 MCP。
7. 需求模糊時先用計畫模式（plan mode）談清楚再做。
8. 用 git 當安全網。
9. 大量閱讀交給子代理，只帶回結論。

另外兩條血淚經驗：

- **保持資料夾乾淨**：代理會讀資料夾裡的雜物並受影響。阿珍遇過資料夾裡留著一個 TTS 資料夾，結果它自作主張加了配音。
- **限流與重試會打斷快取**，成本會突然暴增。

## 環境檢查清單

開工前一次裝好，可以省下代理反覆設定環境的 token（阿珍的建議：第一個任務前先把清單丟給 AI）。

| 工具 | 用途 |
|---|---|
| Node.js 22 以上（建議 24） | 渲染器、預覽伺服器、CLI |
| Python 3.10 以上＋numpy、scipy、Pillow | 音樂分析、歌詞工具、音效合成、品管（Pillow 畫聯絡表與波形圖） |
| ffmpeg（含 ffprobe） | 解碼、編碼、混音、響度量測、聯絡表 |
| Chrome 或 Edge | 無頭渲染 |
| （選用）Blender 4 以上 | 重度 3D |
| （選用）ComfyUI | 在本機 GPU 生成圖片與影片 |
| （選用）npx | Remotion 等 npm 工具（裝在它們自己的資料夾，要你同意才裝） |
| （選用）Demucs、faster-whisper | 人聲分離、自動歌詞對齊 |

`node tools/studio.mjs doctor` 一次檢查全部。選用的工具以 `·` 標示，沒有也不算問題，`doctor` 只回報、不會替你安裝或啟動；它們決定哪些路線走得通（[10](10-render.md#其他工具做的畫面)）。

Windows 注意事項：

- 改系統設定前先備份。有作者為了讓 Claude 桌面版跑起來重裝系統，結果搞錯磁碟代號、清掉了資料碟（奇奇妙妙的类人生物）。

## 技能（Skill）要不要裝

社群有兩派看法，其實不衝突：

- **探索時先不要裝風格類技能**。阿珍與路北路陈都觀察到：技能是固定流程，保證下限但可能限制上限；Multiplane 的作者直說「動畫技能有時是籠子」。很多高收藏作品明確寫了「不要使用已有的技能，不要參考以前做過的影片」。
- **流程類技能有用**。本專案的 `studio` 技能刻意不規定畫風，只提供關卡、檔案結構、量測工具與檢查清單：它管的是「怎麼確認做對了」，不是「該長什麼樣」。

安裝技能的方式：把連結貼給 Claude Code 說「安裝這個技能」，或用外掛市集（見專案 README）。

## 密鑰與權限

- API 金鑰放在 `.env`，**不要貼進對話**。請代理建立 `.env` 範本，你自己填值（言说新事）。
- 在 `.claude/settings.json` 的權限設定裡拒絕讀取 `.env`（`deny: ["Read(./.env)"]`），避免金鑰進入上下文。
- 「略過權限（bypass permissions）」模式只在可信任的專案資料夾使用。

## 多模型分工（選用）

幾位高產作者的分工可以參考：

| 作者 | 分工 |
|---|---|
| 路北路陈（瑞士風格 14.2 萬播放） | Opus 5.5 當設計主管（選題、腳本、分鏡、所有鏡頭程式、音效設計、封面）；Codex 當工程主管（渲染管線、動態模糊、4K60 平行渲染、配音對齊、混音）；兩者透過文件協作：Opus 寫任務規格，Codex 執行並回報，Opus 驗收 |
| plotome（46 分鐘 FIRE 動畫） | Claude 負責程式、動畫、調度與專案管理；GPT 負責審查、挑錯、研究；Gemini 負責初稿文字、聽配音與音樂、TTS |
| 多位作者 | 「Claude 聽不到聲音，所以請另一個 AI 來聽」：用能聽音訊的模型檢查音效與配音 |

單用 Opus 也完全可以完成；多模型的價值主要在**交叉審查**與**聽覺檢查**。
