# 16 常見失敗與對策

症狀 → 原因 → 對策，附出處。遇到問題時先在這裡找。

## 創作

| 症狀 | 原因 | 對策 | 出處 |
|---|---|---|---|
| 「堆料太多，沒有中心」「像作品集」 | 沒有核心概念；鏡頭之間沒有邏輯 | TREATMENT 寫一句話概念、母題、克制預算；分鏡表的 Out 欄位 | 《千本櫻》、穆阿蒂布的留言 |
| 一看就知道是 Opus 做的 | 沒指定風格，收斂到預設風 | 風格卡＋參考圖＋禁用清單 | 《熵》、电子智人、比特新语的留言 |
| 後半段變水、變成投影片 | 上下文太長；提示太簡單 | 分章節、乾淨的上下文、每章同樣嚴格審查；提示寫「故事要用畫面講」 | Apple 50 年、南辰燏炚、十元钱钱 |
| 情緒和原曲不合 | 沒寫情緒基調 | 寫清楚情緒，附參考靜態圖 | 《バカみたいに》的留言 |
| 元素很多，卻沒抓到歌的精神 | 照字面堆元素 | 先寫出這首歌的精神是什麼，再選少數元素 | 《達拉崩吧》的留言 |
| 「很通透但什麼都記不住」 | 知識片沒有旁白或字幕、沒有一個帶得走的重點 | 一支片一個重點；字幕或旁白 | 「Opus 5.5 小曲」的留言 |
| 文案有 AI 味 | 「不是……而是……」「說白了」、連串破折號 | 禁用句型清單；人工潤稿 | plotome、比特新语的留言 |
| 一個元素破壞整體風格 | 只有部分元素照風格規則畫 | 風格規則套用到每一個元素 | 南辰燏炚的留言（非像素的女孩破壞像素風） |
| 網頁 3D 效果不如預期 | 選錯工具 | 第一天測最難的鏡頭；重度 3D 改用 Blender | 可爱归归、plotome |
| 漫畫分鏡很弱 | Opus 不擅長漫畫格的分鏡 | 先寫一份漫畫分鏡規則或技能 | 「melt」PV 作者 |
| 角色像貼紙一樣僵住 | 表演沒有一拍一拍規劃 | 寫出動作節拍：看 → 伸手 → 抓 → 拿起 → 遞出 → 放開 | Tao |
| 角色會「瞬移」 | 沒有連戲規則 | 寫進長期規則 | 可爱归归 |

## 時間與同步

| 症狀 | 原因 | 對策 | 出處 |
|---|---|---|---|
| 歌詞早亮或晚亮 | 把一句時間平均分給每個字；語音辨識錯；寫死秒數 | 逐字對齊；`at.lyric` 定址；`cues.json`；`lyrics snap` | 言炎、mexicat、Nyankomintsu |
| 卡點差半拍 | 強拍相位判斷錯 | 聽點擊預覽；`--first-downbeat` | paint-mv |
| 剪輯節奏快兩倍或慢兩倍 | 速度 2:1 歧義 | 聽點擊預覽；`--bpm` | paint-mv |
| 畫面一直在閃 | 對每個 hi-hat 做反應 | 人聲是主事件，鼓點只做預備與餘震 | EGSECDA、Nyankomintsu |
| 字還沒讀完就換 | 沒有可讀時間規則 | 中文停留 ≈ 字數 ÷ 4.5 ＋ 1.5 秒；歌詞唱多久顯示多久 | lemo-opuscar、Vibe 知識的留言 |
| 段落切換感覺慢了一拍 | 音樂爆發點比第一句歌詞早 | 段落切換放在爆發點，歌詞維持自己的時間 | netsu-ijou |
| 手寫或逐筆出現的字比人聲早 | 規則定成「唱到的那一刻寫完」：筆畫越多，第一筆越早落下（17 畫的「醜」早 0.9 s），觀眾從第一筆就認出字，轉折被筆洩底 | 第一筆落在唱到的那一刻（最多早 0.05 s）；寫不完就跨過下一個音節，必要時加速 | 本專案的練習片（月），獨立評審 |
| 速度會飄的歌越卡越不準 | 現場錄音、自由節奏 | 看 `drift` 報告；分段手動標時間 | paint-mv |
| 逐字時間多出幾個字的位置 | 人聲分軌上的殘響尾巴、長音裡的抖動被當成起音 | 數不合的句子改用點拍 | 本專案 song-to-mv |
| 段落早或晚一小節開始 | 新奇度曲線找到的邊界沒對上停拍或重擊；沒有停拍或重擊可對的邊界常差一到兩小節 | 聽點擊預覽：鈴聲落在錯的小節，就用 `--sections` 重跑 `analyze`（[04](04-music-timing.md#歧義工具要報告不能默默選)） | 本專案的對照實驗 |

## 畫面與渲染

| 症狀 | 原因 | 對策 | 出處 |
|---|---|---|---|
| 轉場時閃一幀白 | 透明度加總小於 1、舞台背景透明 | 舞台用不透明底色 | HyperFrames |
| 偶發黑幀 | GPU 著色器編譯問題；資源還沒載入 | `qa` 偵測黑幀；`ready` 等所有資源；重渲染該段 | 回到Axton（鵜鶘騎單車） |
| 平行渲染的接縫處跳動 | 非決定性：`Math.random`、跨幀狀態、時鐘 | `lint`、`verify`；檢查分段交界 | EGSECDA、Multiplane |
| 渲染非常慢 | 用到軟體渲染（SwiftShader） | 確認 GPU；渲染器偵測到會停止 | EGSECDA |
| 顏色偏、偏暗或偏綠 | ffmpeg 預設 BT.601 | 轉換時指定 BT.709 並標記 | EGSECDA |
| 片尾被切掉 | 用了 `-shortest` | `apad` ＋ `-t` 影片長度 | EGSECDA |
| 中文變方塊或醜的字 | 字型沒載入或缺字，瀏覽器換成替代字 | 字型放專案裡、子集化、引擎的缺字檢查 | Nyankomintsu、mg-styles-15 |
| 中文粗體糊掉 | 瀏覽器合成粗體 | 載入真正的粗體字重 | EGSECDA |
| 縮放中的文字糊 | `will-change`；畫布沒依倍率設定尺寸 | 移除 `will-change`；畫布用實際輸出尺寸 | twoclipping、Multiplane |
| CSS 動畫在輸出裡不動或亂動 | CSS transition／animation 不受 t 控制 | 每一幀由 t 算樣式 | Remotion 技能、Multiplane |
| 交叉溶解變成混濁的雙重曝光 | 兩個複雜畫面重疊 | 錯開，或先退到背景色 | brag |
| 由亮到暗的溶接變灰 | 長時間溶接 | 硬切或模糊出場 | guizang |
| 硬切被動態模糊糊掉 | 子幀跨過剪接點 | 在 `cuts` 宣告剪接點 | Multiplane |
| 動態模糊變成梳狀的重影 | 一格移動幾百 px：子格間距＝單格位移 × 快門 ÷ 子格數，16 子格時十幾 px | 間距超過約 6 px 就加子格（`render.blur`），或放慢那個動作 | 本專案的練習片（月），獨立評審 |
| 鏡頭移動後特效脫離主體 | 每個特效各自算座標 | 只用一個世界到螢幕的轉換函式 | lemo-opuscar |
| 鏡頭一頓一頓 | 鏡頭也跟著「一拍二」 | 手繪層可以一拍二，鏡頭與光每幀都平滑 | lemo-opuscar |
| 長運鏡中段甩一下 | `ease.inOut` 中點的速度是平均的 7.7 倍；`track()` 預設用它 | 幾秒長的運鏡用 `ease.sineInOut` 或 `smoothstep` | 本專案的對照實驗 |
| 切鏡後要找一下主體在哪 | 下一個鏡頭的主體離眼睛原本看的地方太遠 | 主體放在眼睛已經在的地方，或用動作帶過去；看轉場條切點前後兩格 | Walter Murch；本專案的對照實驗 |
| 檔案很大或壓縮後糊成一片 | 頁面裡的顆粒與 CRT 細節吃位元 | 顆粒改在 ffmpeg 加；調整 CRF | lemo-opuscar |
| 渲染器一直等、不開始 | `ready` 永遠是 false（例如 `const` 的暫時性死區錯誤） | 打開預覽頁看主控台錯誤 | lemo-opuscar |
| 出現 NaN、物件消失 | 用 `Infinity` 做運算；`-Infinity + 2 < t` 這類比較 | 檢查邊界值 | papermotion |
| 鏡頭推進時字擠成一團、疊在圖上 | 字跟著移動中的鏡頭排：推進一開始還是舊的尺度 | 字排在鏡頭停住的位置，讓鏡頭推進去對齊 | 本專案 song-to-mv |
| 大字的頂端被切掉 | 「升起」的遮罩框從字的格子上緣開始，字比格子高 | 遮罩框往上多包一列；看最大那個字的靜態圖 | 本專案 song-to-mv |
| 大字在 `studio verify` 不一致 | 超過約 250 px 的字，GPU 會因為之前畫過什麼而差一兩個色階 | `textSprite`：先畫進自己的畫布再貼上 | 本專案風格卡 |
| 大張照片在 `studio verify` 不一致，靜態圖卻每次相同 | 同一張大圖用很多種大小畫（全景到特寫）時，Chrome 會照畫的大小縮小解碼，並沿用先做過的那份解碼，所以一格的像素取決於之前渲過哪些格 | 載入後先用原尺寸畫進自己的畫布，之後都從那張畫布畫 | 本專案的練習片（3072 px 的木炭底圖） |
| 嵌入的畫面蓋掉整頁或掃描線變摩爾紋 | 幾個示範共用一張畫布；CRT 在小格子裡每條掃描線不到 3 列 | 每個嵌入畫面用自己的離屏畫布；小格子先放大畫再縮小 | 本專案 song-to-mv |
| 第一幀是一整片底色 | 第一拍前的預備拍沒有畫面 | 預備拍放片名頁，第一拍切進正片 | 本專案 song-to-mv |

## 聲音

| 症狀 | 原因 | 對策 | 出處 |
|---|---|---|---|
| 「像靜電」「塑膠感、廉價」 | 程式合成音效的上限 | 用授權音效庫或素材本身的聲音；請能聽音訊的模型檢查 | mattshumer、CaCATions |
| 「同一首 BGM 一響就退出」 | 用了迷因 BGM | 每支片用自己的授權音樂 | 比特新语的留言 |
| 「FM 叮叮叮」 | 沒指定樂器 | 指定曲風與樂器 | 《熵》的留言 |
| BGM 讓人焦慮、和內容不合 | 太晚決定音樂方向 | 風格凍結時就決定音樂方向；每章的情緒 | plotome |
| 削波、爆音 | 沒做響度正規化；AAC 編碼後真峰值上升 | 兩階段 loudnorm；編碼後再量一次 | guizang |
| 結尾的高潮一響就沒了 | 片停在高潮後一小節，淡出從高潮後 0.6 s 就開始 | 高潮後至少留一整小節原音，只淡出再下一小節 | 本專案的練習片（月），獨立評審 |
| 持續的低頻轟鳴 | 低頻太多 | 看頻譜圖；28 Hz 高通；低頻比其他頻段低約 3 dB | mg-styles-15、lemo-opuscar |
| 音效太吵 | 每個動作、每次剪接都有音效 | 去彈跳；只替第一個、最後一個、最強的配音效 | papermotion、brag |
| 手機上聲音怪怪的 | 立體聲加寬用了 Haas 效果，單聲道播放時抵消 | 中側（M/S）加寬；檢查單聲道 | mg-styles-15 |
| 旁白有「AI 腔」 | 沒指定 TTS，預設用 edge-tts | 指定旁白引擎 | 阿珍 |
| 旁白很平 | 參考音檔太平；沒寫表演狀態 | 每句前寫表演狀態（「邊笑邊喊，在『青雲之恥』破音」） | 废才俱乐部 |

## 生成素材（混合路線）

| 症狀 | 原因 | 對策 | 出處 |
|---|---|---|---|
| 道具變形、顏色漂、鏡頭亂飄、自己生出文字 | 影片模型每一幀都重畫整個場景 | 影片模型只動綠幕上的單一角色；世界由程式畫 | makevoid |
| 角色多了眼鏡 | 提示裡出現「眼鏡」這個詞 | 審查提示裡的每個字 | 废才俱乐部 |
| 「不要油光」沒有用 | 劇本的「冷汗」蓋過它 | 移除衝突的字，改用別的表演 | 废才俱乐部 |
| 動作變形 | 8 秒裡塞 3 個鏡頭，沒時間做大動作 | 大動作自己一段；脆弱的部位（手）放到畫面外 | 废才俱乐部 |
| 角色和背景像兩層 | 背景參考圖被當成背板貼上 | 用文字描述背景，依距離模糊 | 废才俱乐部 |
| 嘴型不同步 | 用混音驅動嘴型 | 用門控後的人聲分軌；嘴型沒在 2 幀內張開就重抽 | makevoid |
| 畫面文字錯 | 影片模型不會寫字 | 首尾幀；或文字全部由程式畫 | 废才俱乐部、makevoid |
| 便宜的模型反而比較貴 | 重抽率高 | 比較每秒可用畫面的總成本 | 废才俱乐部 |
| 去背後有綠邊、主體被挖洞、背景從柔邊透出來 | 綠幕打光不均、主體顏色接近背景、門檻不對；頭髮、煙、玻璃本來就難去背 | 讀 `studio frames --key` 的量測、打開 `qa/frames_<名稱>.png`；先改素材再調 `--similarity`、`--blend`；半透明的東西讓工具直接輸出透明 | ffmpeg `chromakey`；本專案的自我測試 |

## 流程

| 症狀 | 原因 | 對策 | 出處 |
|---|---|---|---|
| 修好 A、壞了 B | 一次改太多 | 每輪改一兩件事 | 阿珍 |
| 症狀修好了，但做法是錯的 | 代理把原因搞錯 | 當場糾正原因，退回錯的修改 | 路北路陈 |
| 「高一點」變成太高 | 沒給量的參考 | 給參考值或比例 | 路北路陈 |
| 實驗把主線弄亂 | 沒有基線 | git 標籤；實驗在分支上做 | 路北路陈 |
| 方向莫名其妙被帶偏 | 資料夾裡的舊專案、舊技能、雜物 | 保持資料夾乾淨；「不要參考以前做過的影片」 | 阿珍、SeASnAkEss |
| 其他模型寫的交接文件限制了 Opus | 預先消化過的簡報 | 直接給 Opus 原始參考與函式庫 | 奇奇妙妙的类人生物 |
| 第一個任務浪費很多 token 在裝環境 | 環境沒準備好 | 開工前先給環境清單；`studio doctor` | 阿珍 |
| 重裝系統時清掉資料碟 | 沒有備份 | 改系統設定前先備份 | 奇奇妙妙的类人生物 |
| 封號、錯誤、資料外流 | 中轉 API | 只用官方管道 | 留言區反覆出現 |
| 評審手軟 | 代理評自己的作品 | 沒有上下文的獨立評審 | 悬剑听泉、T8star-Aix |
| 細節被漏掉 | 只靠抽樣的畫面檢查 | 加上逐幀的自動檢查 | dhruvalgolakiya |
| 雲端專案事後很難改 | 檔案沒有完整匯出 | 請它匯出所有原始檔與執行說明 | SeASnAkEss |
| 在 Studio 裡調參數，程式被改掉 | Remotion Studio 會寫回程式碼 | 先 git commit | 言说新事 |
| 單次 API 呼叫寫的頁面跑不起來 | 模型沒有實際執行自己的頁面 | 渲染、看過，才相信 | apimodels |
| 成本突然暴增 | 限流與重試打斷快取 | 避免在高峰硬跑；長任務分段 | 阿珍 |
