# 12 提示詞範本

## 先說結論：提示詞沒有咒語

- 穆阿蒂布（world.execute(me)，39 萬播放）：到了 Opus 5.5 這個等級，提示詞工程已經不重要，重要的是和代理溝通，並感受它有沒有理解你要的東西。
- 言说新事：「把需求說清楚，比提示詞的措辭重要」；參考動畫勝過文字。
- 卡尔的AI沃茨與 X 上的 rexan_wong：所謂「一句話」的爆款，背後通常有參考影片、真實素材、三個分鏡方案、先看靜態圖再做動態。

真正有用的不是咒語，而是這幾件事：

1. **素材**：歌、官方歌詞、參考圖或參考影片、角色設定、之前的作品（donaldjewkes 的《Claude Pop》簡報給了原 MV、上一支影片的程式庫、自己的作品資料夾、兩個自訂技能）。
2. **標準**：在最上面寫出品質標準。悬剑听泉的實驗顯示，寫「獲獎級別、高端商用定製」時，Claude 會把目標放在 8–9 分；只說「做好看一點」大約是 6 分。
3. **關卡**：先看計畫與靜態圖，再做動態（見 [03](03-workflow.md)）。
4. **禁用清單**：說清楚不要什麼，那也是需求。

## 七段式導演簡報

把 twoclipping 的六段式、xilo 的七區塊、Lala罐头 的五段公式、Git源宝 的五段提示、mg-styles-15 的風格提示合起來，本專案用七段：

| 段落 | 寫什麼 | 最常見的錯 |
|---|---|---|
| 1. 角色與標準 | 它是誰、品質標準、用什麼流程 | 沒寫標準，得到 6 分的作品 |
| 2. 素材 | 已經有什麼、在哪裡、權利狀態；缺什麼要先問 | 讓它自己上網抓有版權的素材 |
| 3. 方向 | 情緒、概念方向、風格、禁用清單 | 只寫「高級、科技感、震撼」 |
| 4. 結構 | 長度、段落、鉤子、結尾、轉場語法 | 沒寫長度，它做得很長 |
| 5. 製作規則 | 時間來源、決定性、同步、安全 | 寫死秒數、不同步 |
| 6. 檢查與交付 | 每一步怎麼檢查、交出什麼 | 沒有自我審查，你拿到的是 v1 |
| 7. 開始方式 | 先問什麼、先給你看什麼、協作或全自動、預算 | 直接開工，方向錯了才發現 |

Nate Herk 的說法：有了驗證迴圈，你拿到的是第 5、6 版，不是第 1 版。

## 有效的短句

這些片段在高收藏作品裡反覆出現，可以加進你的簡報：

| 短句 | 作用 | 來源 |
|---|---|---|
| 「開始前先問我 4 個決定性的問題」 | 把問題集中在一次 | 风之谷AI |
| 「先給我五個關鍵幀確認，再做完整影片」 | 便宜的方向確認 | 阿珍 |
| 「讓上一步的關鍵物體成為下一步的起點」 | 無縫轉場 | 阿珍 |
| 「故事要用畫面講，不是用文字卡」 | 防止偷懶變成投影片 | Lala罐头 |
| 「不要為了實作方便犧牲畫面的變化」 | 防止整支片重用同一張圖 | Lala罐头 |
| 「做完自己審一遍，有問題改完再給我」 | 自我審查 | plotome |
| 「不要使用已有的技能，不要參考以前做過的影片」 | 測試模型的原始能力、避免被舊專案影響 | 悬剑听泉、SeASnAkEss |
| 「不清楚的地方先跟我確認再開始」 | 避免猜錯方向 | 一起Vibe |
| 「這一版不夠精緻，和〔參考〕差在哪？不要吝嗇時間和 token」 | 讓它自己找差距 | plotome |

## 提示詞的陷阱

- **不要讓弱模型先幫你寫交接文件**。奇奇妙妙的类人生物 做 Bad Apple 時，用其他模型先寫好的交接文件反而限制了 Opus；直接給它參考影片和函式庫比較好。
- **模糊的詞會被字面理解**：scheemunai 寫「90s cartoon」，結果 Opus 理解成 1990 年代，做了一支約 4 分鐘的卡通。
- **給生成模型的提示裡，每個字都可能出現在畫面上**（見 [07](07-style.md#讓生成素材聽話)）。
- **太簡單的提示，後半段會偷懶變成投影片**（十元钱钱）。長片要分章節，或在提示裡要求每段都有畫面敘事。
- **資料夾要乾淨**：舊專案、舊技能、不相干的檔案都會改變它的方向（SeASnAkEss；阿珍的例子見 [02](02-setup.md#省-token-的規則)）。
