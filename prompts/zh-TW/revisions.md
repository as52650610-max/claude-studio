# 修正、審查、交接與重現的提示

> 適合：第一版之後的每一輪。這些提示短，但每一句都在限制範圍或要求證據。
> 背景：[docs/11 審查與品管](../../docs/11-review.md)、[docs/12 提示詞範本](../../docs/12-prompts.md)。

## 第二輪：整體升級

```markdown
這版不錯，但還沒到我要的高度。請分別檢討：
（1）視覺夠不夠驚艷；（2）文字的字型、動態和內容；（3）敘事節奏；（4）有沒有一條線串起全片讓人一次看完。
先列出你打算怎麼改，再動手。
```

## 找差距

```markdown
重看 BRIEF.md 和 TREATMENT.md，再看成品的聯絡表（studio sheet --every 0.5）。
列出「我描述的」和「你做出來的」之間所有的差距，依影響排序，然後做 v2。
```

## 只改指定的地方（省 token 的修正回合）

```markdown
幾乎都很好，不要動。這一輪只改這三件事：
1. `0:42.1` 〔看到的現象〕，原本希望〔效果〕。
2. 〔…〕
3. 〔…〕
規則：只碰相關的檔案；不重構；不探索替代方案；不開子代理。
某個效果試 2–3 次還不行就簡化它，記在 PROGRESS.md。
只為改過的鏡頭渲染靜態圖（剪接後第一幀、主要事件、最後一幀）；沒改的段落用數字比對。
```

## 糾正原因

```markdown
不是〔你以為的原因〕，是〔真正的原因〕。請先把剛才的改動退回，再從〔真正的原因〕改。
```

## 獨立評審

```markdown
請 studio-jury 評審 projects/〔名稱〕 的 out/〔檔名〕.mp4。
只給它專案資料夾和影片路徑，不要解釋你的意圖。把它的分數和修正清單寫進 REVIEW_LOG.md 的新一輪。
```

## 自我審查

```markdown
做完自己審一遍：渲染聯絡表、轉場條、studio qa 報告，找出最糟的三個問題並修好，再交給我。
```

## 凍結

```markdown
這版很好，存成基線（git tag 〔v1-approved〕），之後的實驗都在分支上做。
```

## 把風格整理成風格卡

```markdown
這個風格我很滿意。請把它整理成 styles/〔名稱〕/STYLE.md：
只寫不變的東西（本質、材料與渲染、色彩邏輯、字型、動態質感、鏡頭語法、聲音調色盤、原生招式、媒材的陷阱、可重用的程式、變化空間），
不要寫這支片的故事、BPM 和時間點。
```

## 重現文件

```markdown
如果要從零重現這支片，你會怎麼寫提示與步驟？請寫成 REPRODUCE.md，詳細到另一個代理照著做就能做出來：
規格、技術路線、色彩、字型、筆觸、輸出參數、敘事結構、每一章的做法、遇過的坑、指令的順序。
```

## 跨對話接手

```markdown
先讀 PROGRESS.md 和 BRIEF.md 的長期規則，不要重做已完成的步驟。
告訴我你理解的現況和下一步，然後繼續。結束前更新 PROGRESS.md。
```

## 回饋的句型

| 情況 | 句型 |
|---|---|
| 指出問題 | 「`1:23.4–1:25.0` 這段〔看到的現象〕。原本希望〔效果〕。」 |
| 給檢查方法 | 「數一下參考裡有幾欄，再數你的。」 |
| 只改一處 | 「這個字亮得太早，要在唱到時才亮；只改這一段，其他保持不變。」 |
| 給量 | 「高 40 px」「慢到 0.7 倍」，不要只說「高一點」「慢一點」 |
| 說不要什麼 | 「不要片頭的黑底 Logo。」不要也是需求 |
| 看不出差別 | 「做一個對比頁：左邊基線、右邊新版，同一個時間點。」 |
