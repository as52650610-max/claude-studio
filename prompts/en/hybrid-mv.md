# Hybrid MV brief (code + generative models)

> For: music videos that need real texture or character acting: image or video models make the
> assets; code owns position, structure, motion and every letter.
> How: replace every [bracket]. This route **costs money**: the cost gate comes before the first
> paid request.
> Background: [PLAYBOOK §4 (paid generation) and §8 (hybrid assets)](../../docs/en/PLAYBOOK.md).

```markdown
# Hybrid MV brief

## 1. Role and standard
You are the director, compositor, engineer and producer. Standard: [the texture of a live shoot, the edit of a top music video; nothing that reads as an AI collage].
Follow the studio skill. Code owns position, structure and motion; generative models only make people and texture.

## 2. Assets
- Song: audio/[file], rights: [...]; lyrics: [the official text]
- Generation services: [image model and version], [video model and version]; API keys in .env (never read or print it)
- Character reference: refs/[...] (rights: [...])
- Budget cap: [dollars / credits]; rerolls allowed: [2 per clip]

## 3. Direction
- Style bible: one fixed paragraph pasted verbatim into every image prompt; its hex colours are the same constants the code uses
- Before every text-to-image prompt, a texture rule: [matte skin, visible pores, no smoothing, no shine]
- No tone words in prompts (dark, moody, high contrast): generate neutral flat material and grade everything in compositing
- Not: whole scenes generated by a video model, lettering drawn by a model, removing watermarks or AI labels

## 4. Structure
- Length: [the whole song]; [16:9 1920×1080]; [30] fps
- The world is code plus still backgrounds; a video model animates **one character** per clip: pure green screen #00B140, locked camera, no floor, shadows or props, the whole body in frame with margin
- Full-frame generation at most once or twice, and for a reason
- All on-screen text is drawn by code; if a model must draw text, use first and last frames (first without text, last with the text right)

## 5. Production rules
- **Cost gate**: before the first paid request give me the full timed production script (each clip's length, picture, camera, on-screen words, which reference image plays which role), models and versions, the number of clips, the **number of paid requests**, the estimate and the cap, and the reroll allowance. Start only after I agree
- Keep a receipt per request (parameters, response, file name) so work can resume; a timeout is not a failure and never a reason to resubmit blindly; finished media is never regenerated because of a local error
- Generated frames are never used raw: key, grade, rotoscope, or redraw over them as reference plates
- Times from the songmap, lyrics and cues; the composite is a pure function of t
- Keep generator watermarks and AI labels; CREDITS.md says what was generated

## 6. Checks and delivery
- Before a clip goes into the composite: check hands, faces and props for warping; compare with the model sheet
- studio qa without FAIL; studio-jury ≥ 8
- Deliver: MP4, CREDITS.md (model and version for every generated asset), the receipts list, REPRODUCE.md

## 7. How to start
Ask me at most 5 questions (each with a recommendation); then hand in the clip-by-clip production script and the cost table, and wait for my yes.
```

## While you write

- A video model redraws the background on every frame: props warp, colours drift, the camera
  wanders, text appears from nowhere. So it only ever animates one character.
- Every word in a generation prompt may appear on screen: "glasses must match the reference" can put
  glasses on a character who never wore them.
- A turnaround generated as one image and then cropped stays more consistent than three separate
  generations.
- AI keying: ask the image model to redraw the same picture on pure green, take only its matte, and
  apply it to the original pixels so the face stays untouched.
